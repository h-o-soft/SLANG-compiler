# HUFS (Hu-BASIC と同じ形のディスク)

`x1native_hufs` 環境のディスクです。 Hu-BASIC (CZ-8FB01) と同じ形の 2D D88 で、 OS なしで IPL から起動します。
作ったディスクは、 本物の Hu-BASIC の `FILES` や `INPUT#`、 HuDisk でも一覧・読み書きできます。

いまできること:

- `slangbuild --emit disk -E x1native_hufs` でディスクを作る (`--hufs-add` でファイルを足す)
- ホストの道具 `slfs-pack hu` (作る・一覧・取り出す・足す・消す)
- SLANG から、 ファイルを名前で作る・読む・書く・伸ばす・消す・名前を変える・一覧を見る (`FOPEN` など。 [ファイル API](#ファイル-api))
- SLANG から、 レコードを 1 つずつ直に読み書きする `FRAWREAD` / `FRAWWRITE`

hubasic2sl のファイル命令 (`OPEN` / `PRINT#` / `INPUT#` / `FIELD` / `GET` / `PUT` / `FILES` / `DEVI$` / `DEVO$` など) は、 この環境で組み立てます ([HUBASIC.md の「ファイルの命令」](HUBASIC.md#ファイルの命令-x1native_hufs))。

## 使い方

```sh
slangbuild -E x1native_hufs --emit disk examples/X1NATIVE_HUFS/HUFSRAW.SL -o HUFSRAW \
  --hufs-add GREET.TXT=examples/X1NATIVE_HUFS/files/GREET.TXT,text
```

- `--hufs-add [名前=]ファイル[,bin|,text]` (くり返せる。 名前を省くとファイル名)
  - `,text`: LF・CRLF を CR にして、 終わりに `$1A` を付ける (種類 Asc。 Hu-BASIC の順ファイルと同じ形)
  - `,bin`: 種類 Bin。 大きさの欄に長さ (65535 バイトまで)
  - 何も付けない: 中身そのまま、 種類 Asc
- `--disk-main-name <name>` (と SL の頭の `// disk-main-name:`) で、 IPL の起動名 (= 本体のファイル名) を決めます (既定 `HUFSMAIN`。 `x1native_slfs` と同じ決まり)
- `--slfs-add` は使えません (`x1native_slfs` の物)

この環境には `libx1native_slfs` (`FS_READ_BY_ID` / `FS_SAVE_R` / `FS_SAVE_W`) を入れていません。 これらは "SLFS" の印を確かめずにディスクを読むので、 Hu の形のディスクでは壊れたものを読み書きします。 使うとリンクのエラーになります。

## ファイル API

例: [examples/X1NATIVE_HUFS/HUFSFILE.SL](../examples/X1NATIVE_HUFS/HUFSFILE.SL)

```sl
R = FOPEN(0, "MEMO.TXT", 3);      // 作る (あれば中を捨てる)
R = FWRITE(0, "HELLO", 5);
R = FCLOSE(0);
R = FOPEN(0, "MEMO.TXT", 0);      // 読む
N = FREAD(0, BUF, 64);
R = FCLOSE(0);
```

呼び方 (引数の順、 戻り値は HL) は、 ほかの環境 (lsx・cpm など) の `FOPEN` 系とそろえています。 戻り値と細かい意味は、 この環境のものです (下の表)。

| 関数 | 戻り値 | 意味 |
|---|---|---|
| `FOPEN(fn, name, mode)` | 0 / エラー | ファイル番号 fn (0〜15) で開く。 mode は下の表 |
| `FCLOSE(fn)` | 0 / エラー | 閉じる (緩衝 → FAT → 項目の順に書く)。 エラーでも閉じた扱いにする |
| `FREAD(fn, addr, size)` | 読んだバイト数 | 終わりなら 0。 途中でエラーになったら、 そこまでの数を返す (エラーは `FERR`) |
| `FWRITE(fn, addr, size)` | 書いたバイト数 | 満杯・失敗で途中までなら、 そこまでの数を返す (エラーは `FERR`) |
| `FGETC(fn)` | 0〜255 / `$FFFF` (終わり) / エラー | |
| `FPUTC(fn, c)` | 0 / エラー | |
| `FSEEK(fn, off, whence)` | 0 / エラー | whence 0: 頭から (off は符号なし)、 1: 今から・ 2: 終わりから (off は符号付き) |
| `FSEEKREC(fn, rec)` | 0 / エラー | 位置をレコード rec (0〜1279) の頭に。 64 KB を超える位置はこちらで |
| `FTELLREC(fn)` | 今のレコード番号 | 位置 ÷ 256 |
| `FSIZEREC(fn)` | 確保したレコード数 | |
| `FEOF(fn)` | 1 / 0 | 位置 ≥ 長さ |
| `FERR(fn)` | 最後のエラー (0 = なし) | 読むと 0 に戻る |
| `FDELETE(name)` | 0 / エラー | 開いている・ 書き込み禁止はエラー |
| `FRENAME(old, new)` | 0 / エラー | 書き込み禁止・ new がある、 はエラー (開いているファイルの名前も変えられる。 Hu-BASIC の `NAME` と同じ) |
| `FFIRST(buf)` / `FNEXT(buf)` | 0 (あった) / `$FFFF` (もうない) / エラー | ディレクトリの項目 (消したものは飛ばす) を 32 バイトのまま buf に写す |
| `FFREE()` | 空いているクラスタの数 | 1 クラスタ = 4 KB |
| `FSETBUF(fn, addr)` | 0 / エラー | ファイル番号 2〜15 に、 272 バイトの場所を渡す |

### mode (`FOPEN`)

| mode | 意味 |
|---|---|
| 0 | 読む (ないと `$FF01`) |
| 1 | 読み書き (なければ作る) |
| 2 | 後ろに足す (なければ作る)。 位置を終わり (下の「長さ」) に置く |
| 3 | 作る (あれば中を捨てて長さ 0 にする) |
| +4 | 作るときの種類を Bin にする (既定は Asc。 Hu-BASIC の `OPEN` と同じ) |

### ファイル番号と緩衝

- 0 と 1 は、 ライブラリが緩衝 (272 バイト) を持っています。
- 2〜15 は、 使う前に `FSETBUF(fn, addr)` で、 プログラムが用意した 272 バイトの場所を渡します (`ARRAY BYTE FB2[271];` など)。 渡していない番号を開くと `$FF03` です。
  開いているあいだは、 その場所を書き換えないでください。

### 長さと位置

- **Bin** のファイル: 長さは項目の大きさの欄 (65535 バイトまで)。 閉じるときに、 大きさの欄を書き直します。 65535 バイトを超えて書くと `$FF02`。
- **Asc・Bas** のファイル: 長さはレコード単位 (確保したレコード数 × 256) です。 Hu-BASIC のデータのファイルは大きさの欄が 0 で、 ディスクの上ではレコード単位でしか長さが分からないためです。
  書いて伸ばしたぶんは、 開いているあいだはバイト単位で数えます。 テキストの終わりの `$1A` は、 ファイル API では意味を持ちません (読む側で見てください)。
- 上書きしただけでは長さは縮みません。 縮むのは mode 3 で開いたときだけです。
- 終わりより後ろへ `FSEEK` して書くと、 あいだのレコードも取ります (中身は決まらない)。
- 空のファイルでもクラスタを 1 つ取ります (Hu-BASIC と同じ)。

### エラー

| 値 | 意味 |
|---|---|
| `$FF01` | ファイルがない |
| `$FF02` | ディスクがいっぱい (Bin の 65535 バイトを超えたときも) |
| `$FF03` | 番号が悪い (0〜15 の外・ 緩衝を渡していない) |
| `$FF04` | 開いている (同じ番号で開いている・ 書くものと重なる・ 開いているものを消す) |
| `$FF05` | 開いていない |
| `$FF06` | モードが合わない (読むだけで開いて書いた) |
| `$FF07` | 名前が悪い |
| `$FF08` | ディレクトリがいっぱい (128 項目) |
| `$FF09` | FDC の失敗・ 時間切れ・ ディスクなし。 FAT かディレクトリの書き込みに失敗したあとの書く操作 |
| `$FF0A` | 同じ名前がある (`FRENAME`) |
| `$FF0B` | 書き込み禁止 (ディスクの書き込み禁止と、 項目の書き込み禁止の印 `$40`) |
| `$FF0C` | 扱えない項目 (パスワード付き・ 種類が Bin / Bas / Asc でない・ +1D / +1F が 0 でない) |
| `$FF0D` | 壊れた FAT (鎖が輪になる・ 範囲外や空きを指す) |
| `$FF0E` | 範囲外 (`FSEEK` で頭より前かディスクより後ろ、 `FSEEKREC` で 1280 以上、 `FRAWREAD` / `FRAWWRITE` で 1280 以上) |

### 本物の Hu-BASIC との違い

- 同じファイルを 2 つの番号で開くとき、 読む同士はよいですが、 書くもの (mode 1〜3) があるときは `$FF04` です (Hu-BASIC はエラーにしなかった。 ディスクの中身が壊れるおそれがあるため)。
- 作ったファイルの日付は 0 です (時計を読まない)。

### 書き込みの順と、 途中で止まったとき

書き込みの途中で止まらないこと (原子性) は約束しません。 1 レコードの書き込みと次の書き込みの間で止まったとき、 別のファイルのデータを指してしまう (クロスリンク) ことは起きない順にしています。 どこからも指されないクラスタが残ることはあります。

- **作る:** クラスタを取る → FAT を書く → ディレクトリの項目を書く (`FOPEN` が成功を返す前に、 ここまでする)
- **伸ばす:** データのレコードは緩衝から書き出す。 FAT は写しだけを変え、 ディスクに書くのは `FCLOSE` のとき
- **中を捨てる (mode 3):** 頭のクラスタだけ残す → FAT を書く → 項目の大きさの欄を 0 にする
- **消す:** 項目を消したものにする → FAT を書く
- **閉じる:** 緩衝 → FAT → 項目 (Bin の大きさの欄) の順
- FAT かディレクトリの書き込みに失敗したら、 以後このディスクには書きません (書く操作は `$FF09`)。

FAT の写し (0〜79 番) は 1 つで、 すべての番号から使います。 開いているファイルがないときの `FOPEN`・ `FDELETE`・ `FRENAME`・ `FFIRST`・ `FFREE` で、 ディスクから読み直します (ディスクを入れ替えたときのため)。

### 大きさ

ファイル API を全部使うと、 プログラムの終わり (コードと作業) は、 使わないときより約 3.7 KB 増えます (緩衝 2 本・ FAT の写し・ ディレクトリの緩衝で約 1.1 KB を含む)。 使う関数だけがリンクされます。

## SLANG の関数 (レコードを直に)

### `FRAWREAD` / `FRAWWRITE`

```sl
ARRAY BYTE BUF[255];
R = FRAWREAD(rec, BUF);    // レコード rec (0〜1279) を BUF (256 バイト) に読む
R = FRAWWRITE(rec, BUF);   // BUF をレコード rec に書く
```

- 戻り値: `0` 成功、 `$FF09` FDC の失敗・時間切れ・ディスクなし、 `$FF0B` 書き込み禁止、 `$FF0E` レコード番号が範囲外、
  `$FF04` (`FRAWWRITE`) 開いているファイルがあるときに、 レコード 0〜31 (IPL・ FAT・ ディレクトリ) へ書こうとした
- ファイルの仕組みを通りません (FAT やディレクトリも書けるので、 気をつけて使う)。 開いているファイルがないときに書いたものは、 次の `FOPEN` などで読み直されます
- レコード番号 = トラック × 16 + (セクタ − 1)、 トラック = シリンダ × 2 + 面 (`x1native_slfs` の logical sector と同じ)
- 割り込みは、 1 レコードを読み書きする間だけ止めて、 入口の状態に戻します
- ディスクが入っていないときは、 約 13 秒待ってから `$FF09` を返します
- 同じシリンダのあいだは、 シークしません (ファイル API の読み書きも同じ)。 読み書きに失敗したら、 1 回だけ、 ヘッドを 0 トラックに戻してからシークし直して、 やり直します (ディスクがない・ 書き込み禁止のときは、 やり直さない)

## slfs-pack hu

```sh
slfs-pack hu pack -o <out.d88> --main <main.bin> [--main-name <name>] [--main-load <a>] [--main-exec <a>] [--add <spec>]...
slfs-pack hu list <d88>
slfs-pack hu extract <d88> <name> -o <file> [--text]
slfs-pack hu add <d88> <spec>
slfs-pack hu delete <d88> <name>
```

- `<spec>` は `--hufs-add` と同じ形です
- `extract` の長さ: 種類 Bin は大きさの欄、 それ以外はレコード単位 (Hu-BASIC のデータのファイルは大きさの欄が 0 で、 長さは FAT でしか分からない)。 `--text` は `$1A` の前までにして CR を LF にします
- 書き込み禁止の印 (`$40`) のあるファイルは消せません

## ディスクの形

| レコード | 中身 |
|---|---|
| 0 | IPL (ブートセクタ。 [SLFS](SLFS.md) のブートセクタと同じ形) |
| 1〜13 | `$FF` |
| 14 | FAT (クラスタ 1 つに 1 バイト) |
| 15 | `$00` |
| 16〜31 | ディレクトリ (32 バイト × 128 項目) |

- **クラスタ:** 1 クラスタ = 16 レコード = 4 KB。 2D は 80 クラスタで、 0・1 はシステム。
- **FAT:**
  - `$00` 空き、 `$01`〜`$4F` 次のクラスタ、 `$80`+n 最後のクラスタで n+1 レコードを使う
  - 0・1 番は `01 8F`、 80〜127 番は `$8F`、 128〜255 番は `$00`
- **ディレクトリの項目:**
  - +00 種類 (`$01` Bin・`$02` Bas・`$04` Asc。 `$40` は書き込み禁止。 `$00` 消したもの、 `$FF` ここから未使用)
  - +01 名前 13、 +0E 拡張子 3、 +11 パスワード (`$20` = なし)、 +12 大きさ、 +14 読む番地、 +16 実行番地、 +18 日付 5、 +1E 先頭のクラスタ
- **本体:** クラスタ 2 から続けて置きます (IPL ROM は続いたレコードしか読めない)。 項目は種類 Bin・書き込み禁止 (`$41`)、 名前は起動名、 拡張子は `Sys` です。
- **足すファイル:** 本体の後ろに名前の順で置き、 クラスタは空きのうち番号の小さい方から取ります。
- **日付:** すべて 0 です (組み立てるたびに同じ中身になるように)。

### ファイル名

- 頭の `0:` は飛ばします。 最後の `.` で名前と拡張子に分けます (`.` がなければ拡張子は空白)。
- 名前 1〜13 文字、 拡張子 0〜3 文字。 超えたら切らずにエラー (本物の Hu-BASIC も Bad file descriptor)。
- 使える字は ASCII の印字できる字と半角カナです。 `"`・`:` は使えません。
- 比べるときは大文字と小文字を区別します (本物の Hu-BASIC と同じ)。
