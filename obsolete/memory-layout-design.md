# メモリレイアウトと変数初期化の設計検討

## 現状の問題

現在の新コンパイラでは、初期値付き変数と配列で初期化方式がチグハグ:

```
VAR A=10           → _A: DS 2 + エントリポイントで LD HL,10; LD (_A),HL  (実行時コピー)
ARRAY D[2]={1,2,3} → _DATA: DB $01,$02,$03                              (コード領域埋込み)
```

- 変数: RAM安全（実行時に書き込む）だがROM環境で冗長
- 配列: ROM環境で書き換え不可の問題あり

## 元の仕様（Oh!X 1988年）

> =定数式とすることにより、変数の初期化をすることができる。
> この場合、WORK宣言がなされていても、その変数のワークはプログラム中に埋め込まれる。
> この初期化はコンパイル時にのみ行われ、実行時には行われない。

**前提: 全RAM環境（S-OS）**。プログラムもデータもRAM上にあるので、
コード領域の初期値がそのまま変数として読み書き可能。

## ROM環境での問題

MSX ROM環境など、コードがROM上に配置される場合:

```
_A: DW $000A    ; ROM上 → A=20 で書き込むと失敗/未定義動作
_DATA: DB 1,2,3 ; ROM上 → DATA[0]=99 で書き込むと失敗
```

## 理想的な設計: text/rodata/data/bss セクション

### セクション定義

```
.text    (ROM)  コード（関数本体）
.rodata  (ROM)  読取専用データ（CONST、文字列リテラル、初期値テンプレート）
.data    (RAM)  初期値付き変数・配列（起動時に.rodataからコピー）
.bss     (RAM)  初期値なし変数・配列（ゼロクリアまたは未初期化）
```

### 各宣言のセクション配置

| 宣言 | .text | .rodata | .data | .bss |
|------|-------|---------|-------|------|
| 関数本体 | ✓ | | | |
| CONST X=10 | | EQU | | |
| CODE(...) | ✓ (インライン) | | | |
| 文字列リテラル | | ✓ | | |
| VAR X | | | | ✓ DS 2 |
| VAR X=10 | | ✓ DW 10 (テンプレート) | ✓ DS 2 | |
| VAR X:$C000 | | | EQU (固定) | |
| ARRAY D[4] | | | | ✓ DS 10 |
| ARRAY D[4]={...} | | ✓ DB ... (テンプレート) | ✓ DS 5 | |
| ARRAY D[4]:$8000 | | | EQU (固定) | |

### 起動コード

```asm
; ===  Entry Point ===
    LD  IY, __IYWORK

    ; .rodataから.dataにブロックコピー（連続領域の一括転送）
    LD  HL, __INIT_TEMPLATE    ; ROM上の初期値テンプレート
    LD  DE, __DATA_START       ; RAM上のワーク開始
    LD  BC, __DATA_SIZE        ; 初期値付き変数の合計バイト数
    LDIR

    ; 固定アドレスの初期値付き変数は個別コピー
    ; VAR X:$C000 = 10 のようなケース
    LD  HL, 10
    LD  ($C000), HL

    CALL MAIN
    RET
```

### WORK宣言との関係

```
WORK宣言なし:
  .text → .rodata → .data → .bss → __IYWORK
  すべてコード直後に連続配置

WORK $C000:
  .text → .rodata → .text終端
  $C000～: .data → .bss → __IYWORK
  ワーク領域が別アドレスに飛ぶ
```

### 難しい点

1. **連続配置の保証**: LDIR一括コピーは.data内の変数が連続していること前提。
   固定アドレス変数(:$C000)は連続しないので個別処理が必要。

2. **WORK宣言とコード領域の分離**: WORK指定時、.rodataテンプレートと.dataワークが
   異なるアドレス領域に配置される。アセンブラレベルでORGを使い分ける必要あり。

3. **全RAM環境との互換性**: S-OS等の全RAM環境では、仕様通り「コード内埋込み」が
   メモリ効率的に優れる（テンプレート+ワークの二重確保が不要）。
   → env_typeで戦略を切り替えるのが理想。

4. **初期値付きローカル配列**: 局所宣言では初期化不可（仕様通り）なので問題なし。

## 段階的な実装方針

### Phase 1: 統一（現在 → 次回）
- 変数と配列の初期化方式を統一する
- まずは「全部実行時コピー」で統一（ROM安全、若干冗長）
- 初期値テンプレートは.rodata的にコード領域に配置
- ワークは.data/.bss的にDS確保
- LDIR一括コピーの起動コード生成

### Phase 2: 環境別最適化
- env_typeに応じて初期化戦略を切り替え
- 全RAM環境: 仕様通りのコード内埋込み（テンプレート不要）
- ROM環境: テンプレート+ワーク+LDIRコピー

### Phase 3: セクション分離
- .text/.rodata/.data/.bss を明示的に管理
- シンボルテーブルに配置セクション情報を持たせる
- CodeGeneratorでセクション別に出力
- AILZ80ASMのセクション機能との連携

## 現状の対応

現時点では:
- 変数: 実行時コピー方式（ROM安全）
- 配列: コード内埋込み方式（ROM非安全）
- **配列も実行時コピー方式に統一すべき**（Phase 1）
