## SPRLIB — X1 スプライトライブラリ (GVRAM)

16x16 のソフトウェアスプライトを最大 8 枚、グラフィック VRAM 上で管理する
ライブラリです。ハードウェアスプライトを持たない X1 のグラフィック VRAM に
対して、ダブルバッファ + "old1 erase" 方式によりチラつきなく描画します。

- 座標はすべて **4 ドット単位**
- スプライトパターンは **96 バイト固定** (16x16 × 3 プレーン)
- `SPR_UPDATE()` 内部でページフリップまで行う

### 前提と呼び出し順序

```slang
WIDTH(40);       // 320x200 モード
GRPSETUP();      // グラフィック VRAM 初期化
GRDISP(1);       // グラフィック表示 ON
SPR_INIT();      // この順序で呼ぶ (SPR_INIT が副作用として下記を行う)
```

`SPR_INIT()` の副作用:
- GVRAM (`$4000-$FFFF` = B/R/G 3 プレーン 48KB) を 0 クリア
  - **テキスト VRAM / アトリビュートは触らない**ので、TILELIB と組む
    ときも初期化順を気にせず呼んで OK
- CRTC reg12/13 をダブルバッファ用に初期化 (デフォルト描画ページ = 4)
- パレット priority を "0 = 後面, 1〜7 = 前面" に設定

### スプライトパターン フォーマット (96 バイト固定)

```
 0..31  : B プレーン (16 行 × 2 バイト)
32..63  : R プレーン (16 行 × 2 バイト)
64..95  : G プレーン (16 行 × 2 バイト)
```

各行 2 バイトで 16 ドット幅 (byte 0 が左 8 ドット / ビット 7 が左端)。
OR 描画のため、**全プレーン値 0 のビットは透過** として扱われます。

例: 白ダイヤモンド (一部抜粋、B/R/G とも同じパターン)

```
DB $01,$80    ; ........1 1.......    (行 0, 中央 2 ドット)
DB $03,$C0    ; .......11 11......    (行 1, 中央 4 ドット)
DB $07,$E0    ; ......111 111.....    (行 2, 中央 6 ドット)
...
DB $FF,$FF    ; 11111111 11111111    (中央行, 全 16 ドット)
```

色の作り方:
- 青のみ → B プレーンだけに値を入れる (R/G は 0)
- 白 → B/R/G 全プレーンに同じ形を入れる
- シアン (B+G) → B と G だけに値を入れる

詳しくは `SPRTEST2.SL` (各色 1 プレーンずつ並べる診断例) を参照。

### API 一覧

| API | 引数 | 動作 |
|---|---|---|
| `SPR_INIT()` | — | VRAM クリア / CRTC / パレット初期化 (`WIDTH`, `GRPSETUP`, `GRDISP` の後で呼ぶ) |
| `SPR_SET_PATTERN(id, ptr)` | id 0..7, パターン先頭 | スプライト id のパターン (96 バイト固定) を登録 |
| `SPR_SET_POS(id, x, y)` | id, x, y (いずれも 4 ドット単位) | 位置を設定。**範囲: x=0..78, y=0..46** (16 ドット幅ぶん余裕) |
| `SPR_SET_SHOW(id, visible)` | visible: 0=非表示, 非0=表示 | 可視フラグを更新 (非表示化時は次フレームからフェードアウト) |
| `SPR_IS_ACTIVE(id)` | id | フェードアウト中など「まだ描画が残っている」なら 1, 完全に消えていれば 0 を返す |
| `SPR_UPDATE()` | — | **毎フレーム必須**。全スプライトの消去 → 再描画 → ページフリップ |

### 制約・注意点

- **最大 8 枚** (`SPR_MAX = 8`)
- **座標は 4 ドット単位**。画面範囲外 (x>78 や y>46) を指定すると VRAM
  表示外領域を書き換えてチラつきの原因になります
- `SPR_UPDATE()` を呼ばないとページが進まないので絶対に毎フレーム呼ぶこと
- OR 描画: プレーン値 0 のビットは既存 GVRAM を保持 (透過)。背景には自然に
  乗りますが、**スプライト同士が重なると描画順 + OR 合成の影響を受けます**
  (後から描いた方が手前、ではなく色が混ざる)
- 位置を変更しないスプライトも毎フレーム自動的に両ページへ再描画されるので
  アプリ側でダブルバッファを意識する必要はありません
- **`SPR_SET_PATTERN` はポインタを保持するだけ** (データは毎フレーム参照)。
  そのスプライトを非表示にするまでパターンデータを生かしておく必要があります。
  動的に書き換えれば次フレームから新しい見た目になります (自前アニメ用途など)

### 最小サンプル

```slang
#include SPRLIB.LIB

ARRAY BYTE SPRITE[] = { /* 96 バイト */ };

VSYNC_PROC() {}

MAIN()
{
	WIDTH(40); GRPSETUP(); GRDISP(1); SPR_INIT();

	SPR_SET_PATTERN(0, SPRITE);
	SPR_SET_POS(0, 20, 12);
	SPR_SET_SHOW(0, 1);

	LOOP {
		// ここでキー入力やロジック
		VSYNC(1);
		SPR_UPDATE();
	}
}
```

### 収録サンプル

| ファイル | 内容 |
|---|---|
| `SPRTEST.SL`  | 最小例。WASD で 1 スプライト移動 |
| `SPRTEST2.SL` | B / R / G / 白の各プレーンを並べた色確認用 |
| `SPRTEST3.SL` | 複数スプライト + パーティクル (`SPR_IS_ACTIVE` による再利用) |

### TILELIB と併用する場合

`TILESPR.LIB` (統合 shim) を `#include` することで、`TILELIB` と
`SPRLIB` のページを同期するヘルパー `TILE_SYNC_SPR_PAGE()` が使えます。
詳細は `examples/tilespr/` 配下を参照してください。
